# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Upstream contribution policy

`CONTRIBUTING.md` contains an explicit **AI/LLM policy**: the upstream yt-dlp project closes issues and PRs generated by LLMs, and may block the submitter. Their rationale includes an Unlicense (public domain) licensing concern. Keep this in mind before proposing that work here be sent upstream — that decision belongs to the user.

## Commands

The project uses [`hatch`](https://hatch.pypa.io) (>=1.10.0) as its project manager. `hatch` is **not installed in this container**; `pytest`, `ruff` and `uv` are on `PATH` but are not importable as modules (`python3 -m pytest` fails — use the `pytest` binary or `devscripts/run_tests.py`).

```shell
# --- with hatch (preferred when available) ---
hatch run setup           # install pre-commit hook (.pre-commit-hatch.yaml)
hatch fmt                 # ruff --fix + autopep8 --in-place
hatch fmt --check         # check only
hatch test                # core tests
hatch test YourExtractor  # single extractor's download tests
hatch run yt-dlp <args>   # run the CLI from the working tree

# --- without hatch ---
python3 -m devscripts.install_deps --include-group dev   # or: pip install -e ".[default,dev]"
python3 devscripts/run_tests.py                # core tests (== -m "not download")
python3 devscripts/run_tests.py core           # same
python3 devscripts/run_tests.py download       # network tests (-m download)
python3 devscripts/run_tests.py YourExtractor  # expands to test/test_download.py::TestDownload::test_YourExtractor
python3 devscripts/run_tests.py test/test_utils.py::TestUtil::test_url_basename
python3 devscripts/run_tests.py -k EXPRESSION  # passthrough to pytest -k
python3 devscripts/run_tests.py --pytest-args '--reruns 2 --reruns-delay 3.0'
ruff check . && autopep8 --diff .              # what CI's "Code check" job runs
make offlinetest                               # codetest + pytest -Werror -m "not download"
./yt-dlp.sh <args>                             # run the CLI from the working tree
```

Notes on tests:
- Tests run under `-Werror`; a new `DeprecationWarning` from your change will fail the suite.
- Extractor tests are generated from each extractor's `_TESTS` list. Multiple tests become `test_YourExtractor`, `test_YourExtractor_1`, `test_YourExtractor_2`…; `test_YourExtractor_all` runs them all. Entries with `only_matching` don't count toward numbering.
- Flaky tests run by default locally and are disabled in CI (`--no-flaky` / `--disallow-flaky`, plumbed through `test/conftest.py`).
- For tests needing credentials, create `test/local_parameters.json` (gitignored) with `usenetrc`/`username`+`password`/`cookiefile`; it is merged over `test/parameters.json`.
- `test/conftest.py` defines the `handler` fixture plus `skip_handler`/`skip_handler_if`/`skip_handlers_if`/`handler_flaky` markers — networking tests are parameterized across request handlers.

Build/codegen:
```shell
python3 devscripts/make_lazy_extractors.py     # generates yt_dlp/extractor/lazy_extractors.py (gitignored)
python3 devscripts/update-version.py           # date-based version bump
python3 -m bundle.pyinstaller                  # standalone executable
make yt-dlp                                    # zipapp binary; `make` also regenerates docs/completions
make                                           # lazy-extractors + binary + README/manpage/completions/supportedsites
```
`README.md`, `supportedsites.md`, `yt-dlp.1`, shell completions and the issue templates are **generated** from `yt_dlp/options.py` and the extractor list — edit the sources, then regenerate via `make doc`, never hand-edit the generated files.

Commit messages follow the changelog-scoped style: `[ie/sitename] Fix extractor`, `[ie] ...`, `[core] ...`, `[build] ...`, `[ci] ...`, `[cleanup] ...`, `[devscripts] ...`, `[rh:curl_cffi] ...`. `devscripts/make_changelog.py` parses these prefixes.

## Architecture

### Request flow

`yt_dlp/__init__.py:main` → `options.py:parseOpts` (optparse) → `validate_options`/`parse_options` translate CLI switches into a `params` dict → `YoutubeDL(params)` → `YoutubeDL.download(urls)`.

`YoutubeDL` (`yt_dlp/YoutubeDL.py`, ~4.5k lines) is the orchestrator and also the public embedding API. Its pipeline:

1. `extract_info(url)` — picks the first `InfoExtractor` whose `suitable()` matches, calls `ie.extract(url)`.
2. `process_ie_result()` — resolves the returned *info dict* by `_type`: `url`/`url_transparent` recurse into another extractor, `playlist`/`multi_video` go through `__process_playlist`, `video` falls through.
3. `process_video_result()` — normalizes fields, runs `build_format_selector`/`sort_formats` (the `-f`/`-S` mini-language lives here), applies `_match_entry` filters.
4. `process_info()` — writes metadata/subtitles/thumbnails, picks a downloader, downloads, merges, then `post_process()`.

Postprocessors are keyed by *when* they run — `utils.POSTPROCESS_WHEN` = `pre_process`, `after_filter`, `video`, `before_dl`, `post_process`, `after_move`, `after_video`, `playlist`. `YoutubeDL._pps` is a dict of lists keyed by those stages and `run_all_pps(key, info)` dispatches each one.

The **info dict** is the central data structure; its full field contract is documented in the `InfoExtractor` class docstring in `yt_dlp/extractor/common.py` (~lines 119–440). Only `id` and `url`-or-`formats` are mandatory — extraction of every other field must be non-fatal (`fatal=False`/`default=None`), so a layout change on the site degrades metadata instead of breaking the extractor.

### Extractors (`yt_dlp/extractor/`)

~1000 site modules. Registration is a three-hop chain worth understanding before touching it:

- `_extractors.py` — a flat, alphabetically-sorted list of `from .site import SiteIE` imports. **Every new extractor class must be added here**, and the class name must end in `IE`. In a parenthesized import group the last entry needs a trailing comma or the formatter will reflow it.
- `extractors.py` — tries `lazy_extractors._CLASS_LOOKUP` first (generated, fast startup), falls back to importing `_extractors`. Ordering matters: YouTube is placed first for match speed, `GenericIE` last as the fallback. Set `YTDLP_NO_LAZY_EXTRACTORS=1` to force the non-lazy path.
- `__init__.py` — exposes `gen_extractor_classes()`/`get_info_extractor()` and registers the extractor `PluginSpec`.

Writing an extractor: subclass `InfoExtractor`, set `_VALID_URL` (a regex with a named `(?P<id>...)` group, or a sequence of regexes; `False` marks an embed-only extractor) and `_TESTS`, implement `_real_extract(url)`. Optional hooks: `_real_initialize`, `_initialize_pre_login`, `_perform_login` (with `_NETRC_MACHINE`). Class flags `_WORKING = False` (broken) and `_ENABLED = False` (not auto-selected) control availability; `_GEO_COUNTRIES`/`_GEO_IP_BLOCKS`/`_GEO_BYPASS` drive the geo-bypass retry in `InfoExtractor.extract`.

`common.py` provides the download/parse helper layer used by every extractor: `_download_webpage`/`_download_json`/`_download_xml` (+ `_handle` variants), `_search_regex`/`_html_search_regex`/`_search_json`, `_og_search_*`/`_html_search_meta`, `_search_json_ld`, `_search_nextjs_data`/`_search_nuxt_data`, and manifest parsers `_extract_m3u8_formats`, `_extract_mpd_formats`, `_extract_ism_formats`, `_extract_f4m_formats`. Prefer these over hand-rolled `re`/`json` code.

YouTube is a package (`extractor/youtube/`) split into `_base.py`, `_video.py`, `_tab.py`, `_search.py`, etc., with two pluggable provider frameworks that have their own READMEs and stable public APIs:
- `youtube/pot/` — PO Token providers (`pot.provider`, `pot.cache`, `pot.utils` are public; the rest is internal).
- `youtube/jsc/` — JS challenge (n/sig) solvers (`jsc.provider` is public).

Both use a `_registry.py` + `_director.py` pattern to select among registered providers.

### Downloaders (`yt_dlp/downloader/`)

`get_suitable_downloader()` maps `info_dict['protocol']` through `PROTOCOL_MAP` to a `FileDownloader` subclass (`HlsFD`, `DashSegmentsFD`, `HttpFD`, `IsmFD`, `FFmpegFD`, …), with special-casing for multi-protocol (`+`-joined) formats and external downloaders (`external.py`: aria2c, curl, wget, ffmpeg). `fragment.py` is the shared base for all segmented protocols.

### Networking (`yt_dlp/networking/`)

An abstraction over multiple HTTP backends. `RequestDirector.send(Request)` sorts its registered `RequestHandler`s by the score from its `preferences` set, then dispatches to the first one whose `validate(request)` doesn't raise `UnsupportedRequest`; if none accept it, `NoSupportingHandlers` collects every rejection reason. Handlers declare `_SUPPORTED_URL_SCHEMES`, `_SUPPORTED_PROXY_SCHEMES` and `_SUPPORTED_FEATURES`, and register themselves via `register_rh` into `_REQUEST_HANDLERS`. Backends: `_urllib.py` (always available), `_requests.py`, `_curlcffi.py` (impersonation), `_websockets.py` — each imported defensively in `networking/__init__.py` so a missing optional dependency degrades instead of crashing. `impersonate.py` holds the browser-impersonation target matching.

### Plugins and globals

`yt_dlp/globals.py` holds process-wide mutable state in `Indirect` boxes (`extractors`, `postprocessors`, `plugin_*`, `LAZY_EXTRACTORS`, `supported_js_runtimes`, …) so that modules can share state without import cycles. `yt_dlp/plugins.py` implements a custom `importlib` finder over the `yt_dlp_plugins` namespace package: a `PluginSpec` declares a module name, a class-name suffix (`IE`/`PP`) and destination `Indirect`s. Public classes ending in the suffix are collected, honoring `_`-prefixes and `__all__`. Setting `plugin_name=` as a class keyword argument makes a subclass *replace* the built-in it derives from. The plugin/globals API is explicitly documented as having no backwards-compatibility guarantee.

### Utils

`yt_dlp/utils/` re-exports everything through `__init__.py` (`traversal.py` then `_utils.py`, with `_deprecated`/`_legacy` passthrough shims). `traverse_obj` (`traversal.py`) is the workhorse for pulling values out of parsed JSON/XML/HTML and is expected in new extractor code, along with `find_element`/`find_elements`, `subs_list_to_dict`, `require`/`value`. `jsinterp.py` is a pure-Python JS interpreter; `utils/_jsruntime.py` locates external JS runtimes (Deno etc.) for the newer challenge-solving path. `compat/` exists only for old-Python and legacy-API shims — most of its members are banned imports (see below).

## Code style

Enforced by `ruff` (config in `pyproject.toml`, line-length 120) plus `autopep8` for whitespace-only fixes. Beyond what the linter catches, `CONTRIBUTING.md` codifies conventions that reviewers apply:

- **Quotes**: single for strings (even when the string contains `'`), double for docstrings, `'''` only for multi-line. In f-strings, use double quotes inside.
- **Line length**: soft 100-char target, hard 120. Never split string literals (URLs) across lines to fit. Conversely, don't split a line that would fit under 80 chars joined.
- **Trailing parens**: closing paren goes on the last argument line for calls/grouping; multi-line list/dict/tuple/set literals close on their own line.
- **Inline values**: don't hoist a single-use variable (especially a regex) away from where it's used.
- **Collapse fallbacks**: pass a list of patterns to `_search_regex`/`_html_search_regex`/`_og_search_property`/`_html_search_meta` instead of chaining `or`.
- **Safe conversions**: wrap extracted data in `int_or_none`, `float_or_none`, `url_or_none`, `unified_strdate`, `unified_timestamp`, `parse_duration`, `parse_resolution`, `parse_count`, `parse_age_limit`, `traverse_obj`, `try_call`.
- **Regexes**: non-capturing groups when the group isn't used; keep them relaxed/flexible against markup churn (`[^>]*`, optional attributes) but no more complex than needed.
- `# noqa` is not accepted unless a maintainer asks; the one sanctioned exception is `# noqa: UP031` for printf-style formatting in GraphQL query templates.
- Several stdlib modules are **banned from `from X import Y`** in extractor files (`re`, `json`, `os`, `functools`, `itertools`, `urllib.parse`, …) — import the module and qualify. Legacy `yt_dlp.compat`/`yt_dlp.utils` names (`compat_str`, `encodeFilename`, `bytes_to_intlist`, `try_get`-era helpers, …) are banned with per-name replacement messages in `[tool.ruff.lint.flake8-tidy-imports.banned-api]`.
- isort ordering and `flake8-print` are enforced **only** inside `yt_dlp/extractor/**`.
- Supported runtimes are CPython >= 3.10 and PyPy >= 3.11 — no backports needed below that, no newer syntax allowed above it.
- CI also asserts every file under `yt_dlp/` has mode `100644`.
